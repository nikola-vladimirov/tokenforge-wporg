What it is

This manual describes TokenForge 0.58.2.

TokenForge is a design system you set up once and use everywhere. Colours, type and spacing scales, layout, buttons, cards, icons, effects and more are CSS variables and classes. They are built into one static stylesheet. It loads on your front end, in the block editor and, when a supported page builder is active, in the builder.

Everything runs on your own site. There is no account and no licence key. TokenForge is free under the GPLv2 or later. The only outside service is Google Fonts, and only when you ask for it (see Privacy and external services).

Requirements

  • WordPress 5.9 or newer. The plugin is tested up to WordPress 7.1.
  • PHP 7.4 or newer.
  • An administrator account. The TokenForge menu is for users who can manage options.
  • Optional: WooCommerce, for the shop styles. A supported page builder, for the builder tools (the Builders section lists them).

TokenForge works on any WordPress site. The builder tools switch on only when a supported builder is active.

How it works

You change settings in the dashboard and press Save. TokenForge then writes the stylesheet to uploads/tokenforge/. The CSS is built when you save, not on every page load. With WooCommerce, the shop styles go into a second file that loads only on pages that show the shop. While "Leave out unused utility classes" is on, a separate file with every class is also written, for the builder canvas.

What a new site starts with

  • A complete starter design system: every token, colour family and setting is already there, so there is nothing to import.
  • The Effects module starts switched off. Switch it on at Home when you want effects.
  • The automatic accessibility attributes all start off.
  • The tools for AI agents start on.

You can reset to the starter values at any time, for everything or for one part. See Import, export and reset.

Install and first steps

Install

  1. Upload the tokenforge folder to /wp-content/plugins/, or install the zip from Plugins > Add New > Upload.
  2. Activate the plugin. A new site starts with the starter design system. If the builder in use supports theme styles, TokenForge links or creates a theme style for the whole website on the next page load.
  3. Open TokenForge in the admin menu, change what you like and save.

First steps

The Home screen has a Getting started list. These are its six steps, in order (Connect the builder shows only when a supported builder is active):

  1. Pick your colours. Set the base colour of each family on the Colors screen. The shades and the dark mode values are made for you.
  2. Set your fonts. On Typography, upload your font files or copy a Google font to your site, then choose the body and heading fonts.
  3. Check the fluid scales. Text and spacing grow smoothly between the smallest and the largest screen width you set on Typography.
  4. Style buttons and links. One look for every button. Each colour family gets its own variant.
  5. Connect the builder. The theme style, classes and variables follow TokenForge, and changes made in the builder come back.
  6. Keep a backup. Export everything to a file before big changes. You can import it on another site.

Then open Accessibility and look at Palette contrast. It lists text and button colours that are hard to read, with a suggested fix.

Saving

The top bar has three buttons. Save (also Ctrl + S, or Cmd + S on a Mac) stores your changes and rebuilds the stylesheet. Regenerate rebuilds the stylesheet without changing anything. Discard changes appears while you have unsaved changes and undoes every change since the last Save.

The setup wizard

If the active builder supports it, the Setup wizard sets the builder's own settings the way TokenForge works best and connects the two. Until it has run, Home shows a card with the text "New site? Set up the builder in one go." The wizard has two steps:

  • Step 1: builder settings. Seven groups, each one optional: Working in the builder, Previews and smart inputs, Classes and CSS, Faster pages, Forms and queries, Media health and No automatic screenshots. Each group shows how many of its settings would change. Settings that are already right are left alone.
  • Step 2: connect TokenForge and the builder. Three parts: send TokenForge's variables, colours and classes to the builder; load TokenForge's stylesheet in the builder canvas; link the site's theme style to TokenForge.

You choose what is ticked, then press Apply. Undo builder settings puts the builder's settings back as they were before the first run. The wizard never touches site-specific settings such as licences, API keys, user and role assignments or remote template sources. You can run it again at any time. Reload the builder after it has run.

Tokens, colours and scales

What a token is

A token is a CSS variable with a name, such as --primary, --space-m or --text-m. You use it anywhere with var(--space-m). Most tokens come from your settings. Colors makes the colour families. Typography, Spacing, Layout, Borders & Shadows, Icons and Effects make their own variables. All of them are written when the stylesheet is built.

The Tokens screen

This screen lists every variable TokenForge writes, in tabs by category, with a Filter box. The last column, "From / category", says which setting makes a variable, so you know where to change it.

  • + Add token adds your own token: a name, a value and a category. The category can be a built-in one or a new one you name. Your own categories can be renamed or deleted. When you delete one, its tokens move to "other".
  • A token with the same name as a variable a setting makes replaces that variable. A variable made by a setting is read only until you press Change, which adds your own value for it.
  • Use settings removes the tokens that only repeat what a setting makes, have no effect, or are colours left over from an older palette. Tokens with a value of their own stay.
  • Find uses looks through your pages, templates, classes and styles for every var(--...). It only reads. Afterwards Unused shows only what is used nowhere.
  • The On column switches a token on or off.

Colour families

The starter design system has eleven families: primary, secondary, tertiary, accent, base, neutral, action, success, danger, warning and info. Each one is made from a single base colour. TokenForge makes the base colour, a hover step and six shades (ultra-light, light, semi-light, semi-dark, dark and ultra-dark) in OKLCH.

The variables follow the family name: --primary, --primary-hover, --primary-light, --primary-ultra-dark and so on. A family also gets -ref and colour channel variables (--primary-hex, --primary-rgb, --primary-hsl, --primary-h, --primary-s, --primary-l, --primary-r, --primary-g and --primary-b) and transparent steps from --primary-trans-10 to --primary-trans-90.

  • Change a colour on the Colors screen, then Save. The family is regenerated.
  • Dark mode colour. Each family has an optional dark mode colour for its base and hover. Empty means the same as light mode. The shades always swap: ultra-light becomes ultra-dark. "Dark mode fine tuning" sets the lightness (0 to 1) and chroma (0 to 0.4) of the main colour and its hover.
  • Switch a family off to drop all its variables from the stylesheet. Classes that use them lose their colour.
  • Add a family with a name and a base colour (the Add family button). Your own families have a Remove button. The standard ones do not.
  • Shade generation controls how every family is made: the same lightness for brand colours and for status colours, the base lightness (0.3 to 0.9), the transparent steps and the dark mode values as their own variables (--primary-alt).

Dark mode

Dark mode is set on the Colors screen, in the Dark mode panel.

  • Dark values is "Off (light only)" or "On (light-dark())". When it is on, every colour token also gets a dark value, written with light-dark(). A new site starts with it on.
  • Site default is "Follow the visitor’s OS", "Light" or "Dark". A new site starts with Light.
  • Visitor light/dark switcher lets visitors choose. It is off on a new site. Add the switch anywhere with the shortcode [tokenforge_scheme_toggle] (it takes a class attribute), with the Light/Dark Toggle element or block, or with the class scheme-toggle or the attribute data-scheme-toggle on any button. The choice stays in the visitor's own browser.
  • Always dark (selectors) and Always light (selectors) keep their scheme whatever the site does, for example a footer.
  • The classes .scheme--light and .scheme--dark, and the attribute data-scheme="dark", force a scheme on any element and everything inside it.

Color assignments are the named colours behind .bg--ultra-light, .bg--light, .bg--dark, .bg--ultra-dark and the text colours .text--dark, .text--dark-muted, .text--light and .text--light-muted. A .bg--* class sets a background and a readable text colour. Background relationships shows what each .bg--* sets for everything inside it: text, headings, links, the colour family of buttons and the icon scheme. Add .unrelate to a button to keep its own colours.

Fluid scales

On Typography you set a viewport range: the narrowest and the widest screen width (the starter values are 360 and 1366 px). Every fluid value grows smoothly between them. Each scale has a base size and a ratio at both ends.

ScaleVariablesSet on
Text--text-xs to --text-xxl (m is the base)Typography > Text scale
Headings--h1 to --h6 (h4 is the base)Typography > Heading scale
Space--space-xs to --space-xxlSpacing > Space scale
Section spacing--section-space-*, the space steps times a multiplierSpacing > Section spacing
  • The starter text scale is a base of 16 px on the narrowest screen and 18 px on the widest, with a ratio of 1.2 growing to 1.333.
  • Overrides replace a single computed size, one per line, such as h1-max=64 or space-xs-min=8.
  • Transition variables add "-to-" variables such as --text-l-to-m and --space-xl-to-m: the larger step on desktop, easing down to the smaller one on mobile.
  • Generate fluid scales is the master switch. Turn it off only if you define those variables yourself.
  • Root font size (%) (Typography) is the html font size as a percentage of the browser default. At 100%, 1rem is 16 px. At 62.5%, 1rem is 10 px. Every px to rem conversion uses it.

Width, grid and other tokens

  • Content width (px) (Layout) is the maximum width of your content (the starter value is 1366). It makes --content-width and the gutter-aware --content-width-safe. The width scale adds --width-10 to --width-90 (percentages of the content width) and --width-xs to --width-xxl.
  • Grids (Layout) make --grid-1 to --grid-12, the ratio variables such as --grid-2-1, --grid-gap and, when Auto grids is on, --grid-auto-2 to --grid-auto-12.
  • Radius makes --radius and --radius-xs to --radius-xxl. Borders make --border, --border-light and --border-dark. Box shadows make --shadow-1 to --shadow-5.
  • Breakpoints (Options) name the widths used by the responsive classes and recipes. The starter values are xs 478, s 767, m 991, l 1279, xl 1439 and xxl 1919 px.

Fonts

  • Self-hosted fonts (Typography). Upload a .woff2, .woff, .ttf or .otf file, or paste a URL. TokenForge turns TTF and OTF files into WOFF2. If your server cannot make WOFF2 (it needs the Brotli extension), it makes WOFF instead. Each file is one entry with a family name, weight, style and font display. A variable font, a fallback file, preloading and a character range are optional. Uploads are stored in uploads/tokenforge/fonts/.
  • Download from Google Fonts. Enter a family name and the weights, then press Download to this site. The files are copied to your server once, so visitors never contact Google. See Privacy and external services.
  • The switches "List the families in the builder font picker" and "List them in the block editor font picker" add your families to those pickers. Then use the family name anywhere, for example as the Body text font family.
  • Preload only the one or two fonts that show at the top of the page. Preloading many fonts slows the page down.

Utility classes and the cheat sheet

The utility families

TokenForge writes utility classes for your tokens. Four switches under Options > Utility framework control the families:

  • Colour utilities make text, background and border classes for every colour token, for example text-primary, bg-primary-light and border-primary, and the transparent forms such as bg-primary-trans-40.
  • Spacing utilities make padding, margin and gap classes from the space scale.
  • Typography utilities make text size, text style and alignment classes.
  • Layout utilities make grid, flex grid, flex, alignment, display and sizing classes.

Three more switches add optional sets, all off by default. "Link, focus, bullet and column rule colour classes" adds link-{colour}, link-hover-{colour}, focus-{colour}, marker-{colour} and col-rule-{colour} for every colour. It adds about 30 KB. "Colour classes with double dashes too (bg--primary)" also writes the double-dash spelling of the colour classes, such as bg--primary and link-hover--primary, for pages moved from another utility framework. It adds about 10 KB. "Breakpoint variants (-at-xs to -at-xxl)" is described below.

Where the builder supports it, the switch "Register classes with the builder" (on by default) adds the utility classes to the builder's class list, so they autocomplete in its class field.

Coming from another utility framework? Its class names work where the result is the same, for example grid--3 works like grid-3, flex-grid--3 like flex-grid-3 and text--center like text-center. Its breakpoint names are matched by width, so with the starter breakpoints grid--m-2 works like grid-2-at-s (this needs Breakpoint variants). Its colour names with two dashes, such as bg--primary, need the switch "Colour classes with double dashes too (bg--primary)". Names whose result would differ are not copied: use the TokenForge name for those.

Grids

  • grid-1 to grid-12 make equal columns. grid-1-2, grid-2-1, grid-1-3, grid-3-1, grid-2-3 and grid-3-2 make ratio columns. The gap is --grid-gap.
  • auto-grid (also grid-auto) wraps to fewer columns by itself. With "Auto grids" on (Layout > Grids), grid--auto-2 to grid--auto-12 start at that many columns and wrap as space runs out. Add grid--auto-fill, grid--auto-fit or grid--auto-rows to change the flow.
  • Place children with col-span-1 to col-span-12, col-span-all, col-start-N, col-end-N, col-end-last, row-span-N, row-start-N and row-end-N.
  • More: grid-alternate (rows alternate 1:2 and 2:1), ratio auto grids such as grid--auto-1-2 that stack when space runs out, masonry-1 to masonry-5, and order-first, order-last and order-none.
  • Change the columns of any grid at a breakpoint with grid-N-at-{bp} and grid-1-2-at-{bp}, or stack it with grid-stack-at-{bp}. These need Breakpoint variants.

Flex grids

A flex grid puts equal-width items in rows that wrap. A short last row is centred instead of leaving an empty gap on one side.

  • flex-grid-1 to flex-grid-12 set the number of items per row.
  • flex-grid--start and flex-grid--end place a short last row at the start or the end. flex-grid--stretch stretches its items to fill it.
  • flex-grid-N-at-{bp} changes the count at and below a breakpoint, for example flex-grid-2-at-m. This needs Breakpoint variants.
  • The gap is --grid-gap. Set --flex-grid-gap on the element to change it for that grid only.
<div class="flex-grid-3 flex-grid-2-at-m">
	<div class="card">One</div>
	<div class="card">Two</div>
	<div class="card">Three</div>
	<div class="card">Four</div>
</div>

Flex, alignment and other layout classes

  • Display and flex: flex, inline-flex, grid, block, hidden, flex-col, flex-row, flex-wrap, flex-col-reverse, flex-grow, flex-shrink-0.
  • Alignment: items-center, items-start, items-end, items-baseline, items-stretch, justify-center, justify-between, justify-around, justify-evenly, and the self-*, content-* and justify-items-* families. Centring helpers: center-all, center-x, center-y.
  • Size and position: height and max-height (full, screen, 10 to 90 percent), aspect-16-9 and eight more ratios, object-top and eight more positions, sticky-top--s, sticky-top--m, sticky-top--l, opacity-0 to opacity-100, z-0 to z-90, flip-x, flip-y, flip-xy.
  • Columns and clamping: columns-1 to columns-6, col-width-s, col-width-m, col-width-l, line-clamp-1 to line-clamp-6.
  • Container queries: query-container and query-container-size.

Text classes

  • Weight and style: font-100 to font-900, bold, italic, not-italic, uppercase, lowercase, capitalize, normal-case.
  • Lines and wrapping: underline (with wavy, dotted, dashed and double styles), overline, line-through, no-underline, text-justify, text-balance, text-pretty, text-wrap, list-none.
  • Edges and dividers: fade-top, fade-bottom, fade-left, fade-right, fade-block, fade-inline (the length is --fade-amount), border classes per side, and dividers between children: divider--all, divider--top, divider--bottom.
  • Other: selection--alt and focus-parent (the whole card shows the focus ring when its link is focused).

Breakpoint variants

When you switch on Breakpoint variants (-at-xs to -at-xxl), the layout and text classes get a copy for each breakpoint, named {class}-at-{bp}. The breakpoint names are xs, s, m, l, xl and xxl. The class applies at that width and below. Examples: col-span-1-at-m, flex-col-at-s, flex-grid-2-at-m.

The widths come from Options > Breakpoints. Variants are off by default because they add a lot of CSS. Turn on "Leave out unused utility classes" together with them, so only the ones you use stay.

Leave out unused utility classes

This setting (Options > Utility framework) gives visitors a smaller stylesheet. After a scan of your site, TokenForge keeps only the utility classes and the data attribute styles your content uses.

  • The scan reads your pages, templates, menus, widgets and the builder's components. Scan now runs it by hand. A save that switches the setting on runs it too. So does switching on a setting that adds classes (a utility family or the breakpoint variants), so classes your pages already use are kept.
  • A class or attribute you add later joins the stylesheet when you save.
  • The builder canvas and the block editor always have every class and attribute. Variables and components are never left out.
  • Always keep these classes lists names the scan cannot see, because theme files, shortcodes, scripts or another plugin add them. Separate names by new lines, spaces or commas. End a name with * to keep every class that starts with it, for example bg-primary*, or use data-tf-* to keep all the data attributes.
  • After a scan the panel shows how many classes your site uses, and the size of the utility part of the stylesheet with and without the unused classes. If the site has more content than one scan reads, every class stays in.

The Cheatsheet

The Cheatsheet screen lists the classes, variables, recipes and data attributes your site has, each with a plain explanation and the CSS it applies. It is built from your current settings, so a switched-off class is not listed.

  • Groups: Layout & sections, Grids & flex, Spacing, Typography, Colours & backgrounds, Buttons, Cards & forms, Icons, Borders, radius & shadows, Overlays, surfaces & ribbons, Motion & effects, Content & prose, Utilities & accessibility, six groups of variables, Recipes and Data attributes.
  • Search by words. The chips All, Classes, Variables, Recipes and Attributes narrow the list.
  • Click a name or its copy icon. Classes copy without the dot, variables copy as var(--name) and recipes copy as ?name.
  • The same reference is given to AI agents (see Forms, WooCommerce and other features).

Effects

The Effects screen has one panel for transitions, one for each kind of effect and one for the default button effects. The whole module starts switched off on a new site. Switch it on at Home.

Transitions and easing

  • Transition variables make --transition, --transition-duration, --transition-timing and --transition-delay. You set the default duration, timing and delay. A separate switch adds a .transition class.
  • Easing presets (--ease-*) make --ease-* variables from a list of name=value lines. The starter list has names such as smooth, snappy, gentle, bouncy and elastic.

Entrance (scroll)

An entrance effect plays while an element scrolls into view. The classes are .on-enter--fade, --float, --sink, --slide-left, --slide-right, --grow, --shrink and --blur (each starts with .on-enter). Effects combine: on-enter--fade on-enter--float.

  • .on-enter-all--fade and the other -all-- classes on a parent animate every child. Add .on-enter--stagger to the parent to delay each child a little more than the one before. The Stagger interval setting sets the step.
  • .on-enter--parallax moves an element while you scroll, by the Parallax distance.
  • Range start and Range end set where in the scroll the animation runs. The amount of each effect (Float distance, Slide distance, Fade: start opacity and so on) has its own setting.
  • In browsers without scroll-driven animations, a small script plays the entrance once as the element scrolls in. The Fallback duration, Fallback timing and Fallback delay set that animation.
  • Elements that are already on screen when the page opens play their entrance once as the page loads. A hero is a typical case. Before version 0.58.1 such elements waited for a scroll that never came. Elements further down the page still play as you scroll to them.

Exit (scroll)

.on-exit--* and .on-exit-all--* use the same effects as the entrance ones, except parallax, while an element scrolls out of view. .on-exit--stagger works like the entrance one. Their settings mirror the entrance ones; the amounts are named "Fade: end opacity", "Grow: end scale" and "Shrink: end scale".

Visible (once)

.on-visible--* effects play once when an element becomes visible. .on-visible-all--* on a parent does it for every child, and .on-visible--stagger delays each child a little more than the one before. The Threshold (0 to 1) says how much of the element must show first: 0.2 means 20 percent. Without JavaScript the content simply shows. The attribute data-tf-reveal uses these effects too, so the Effects module and the Visible (once) panel must be on for it. data-tf-reveal="fade" fades the element in, and data-tf-reveal="up" fades it in and slides it up into place.

Hover and hover borders

  • Hover: .on-hover--grow, --shrink, --float, --sink, --slide-right, --slide-left, --shadow, --glow, --fade and --brighten.
  • Hover borders: .on-hover--ripple-out, --ripple-in, --outline-out, --outline-in, --underline-left, --underline-center and --underline-right.
  • Button effects: this panel has three lists, Hover, "Entrance (scroll)" and "Hover border". Pick one effect in each, and every TokenForge button (.btn and btn--*, but not btn--none) gets it without a class. All three start on None. Each one only works while its own group above (Hover, Entrance (scroll) or Hover borders) is switched on. With Buttons, "Restyle every button (builder, block editor, plain HTML)" on, the builder, block and plain buttons get them too.

Reduced motion and the builders

  • Visitors who ask their device for reduced motion get no scroll or visible animations and no hover movement. Accessibility > Reduced motion also turns off smooth scrolling for them.
  • "Keep scroll & visible effects still in the builder canvas / block editor" (Effects > Builders & accessibility) stops effects from hiding content while you edit.

Recipes

A recipe is a ready-made snippet you call by name. Type ?name in the builder's custom CSS box, pick it from the list or finish with a semicolon, and it expands into CSS. In a recipe, %root% stands for the selector of the selected element. The Recipes screen has a switch for the whole feature and a list of the built-in recipes with a filter.

Where recipes work

  • The custom CSS box. In every supported builder, TokenForge suggests recipes, variables and classes while you type there. (In one builder the custom CSS box needs the paid version of that builder. The Builders section says which.)
  • Value recipes in style fields. The colour recipes, such as ?primary-clr, expand to a colour with an alpha you can edit. ?color-mix, ?transparency and the six plain gradients (?linear-gradient, ?gradient-radial, ?gradient-conic, ?gradient-sharp, ?gradient-fade and ?gradient-vignette) work the same way. Finish with a semicolon. This needs a builder with style fields and the second switch on the Recipes screen, "Also in builder fields".
  • Text recipes give placeholder copy: ?ipsum-short, ?ipsum (a medium paragraph) and ?ipsum-long. Type the name followed by a space or a semicolon. They work in the builder's text fields, text areas, rich text and text edited on the canvas, in the block editor canvas and in the block editor's sidebar text fields. Code editors are left alone.

The TokenForge window

The window is the whole dashboard, docked inside the builder. Open it with the shortcut (set under Options > TokenForge window; the starter value is Alt + Shift + T) or the TokenForge button. It is shown to administrators only. It is the same dashboard, so every screen is there. Where the builder supports it, "Show in builder canvas while editing" adds a TokenForge button in the corner of the canvas. While dark mode is on, a small moon button beside the TokenForge button switches the canvas between light and dark, so you can check both colour schemes while you edit. Only you see it and nothing is saved (Builder, Dark mode preview switches it off). The window also opens on your site's pages for administrators, with the shortcut or the admin bar link.

Right-click menus

  • Right-click a style field to insert a TokenForge variable. Where the field has a unit, such as Elementor's size fields, it switches to its custom unit by itself.
  • Right-click the class field to add or remove TokenForge classes on the selected element. The builder's own Save keeps them.
  • Shift + right-click opens the browser's own menu.
  • The switches are under Builder > Contextual menus.

The input helper

Leave a style field or press Enter. A TokenForge variable typed by name (space-m or --space-m) becomes var(--space-m). Maths with a variable, such as var(--space-m) * 2, is wrapped in calc(). A name with no dash in it, such as primary, needs the two leading dashes. Anything else stays as typed, and the builder's undo takes the change back. The switch is "Turn typed variable names and maths into var() and calc()" under Builder > Inputs & class list.

What only Bricks has

  • Sync, both ways. Your tokens become the builder's global variables, your colour families fill a colour palette, and the utility classes join the class list. Options > Builder sync has a switch for each part. Changes made in the builder come back into TokenForge.
  • Theme style. One theme style for the entire website follows TokenForge: its fonts, sizes, colours, container width and section padding point at TokenForge variables. A change you make in the theme style comes back into TokenForge. The switch is "Keep a theme style in step with TokenForge".
  • Style Manager. The text, heading and space sizes show as typography and spacing scales, and the HTML font size, screen widths and default mode fill its Settings. A change made there comes back into TokenForge. Only administrators change TokenForge from there.
  • Page check and Design check (Accessibility > This page). Nothing runs until you press Run check (or Run design check). The page check lists accessibility problems on the page you are editing, worst first. Show selects the element. Where it is safe, Fix changes it. A fix changes only the open page in the builder, nothing is saved until you save, and the builder's Undo takes it back. The Design check lists colours and font sizes typed by hand where a token is close, contrast in light and dark mode, and sizes off the type scale. The check uses the open source axe-core engine, bundled with the plugin.
  • BEM class generator. Hover a row in the Structure panel and press its code brackets icon ("Generate BEM classes"). A dialog reads that element and everything inside it, names the classes in the block__element pattern from each element's label, and applies them as global classes when you press Apply Classes.
  • Canvas and Add Elements tools: outlines for containers, grids and overflowing elements; heading level and focus order badges; one element per row, a denser Add Elements panel and a list of elements to hide.
  • Style tab and templates: the CSS group first, a taller code editor, remote templates that keep their own classes and a tidier template gallery. The panel "Builder built-in" changes the builder's own settings, so reload the builder after saving.
  • Forms and the setup wizard (see Forms, WooCommerce and other features and Install and first steps).
  • AI guidance. The builder's own start-here guide tells an AI agent to use TokenForge. See Forms, WooCommerce and other features.

Add-ons for builders

A developer can load scripts and styles in the editor of every supported builder with the action tokenforge_builder_enqueue. See For developers.

The block editor

The block editor works on any site. Everything for it is on the Block editor screen. The screen shows while the block editor is in use, and every switch has a tooltip. Reload the editor after saving.

Presets

Your colours, font sizes, spacing, font families and shadows become the presets the editor offers. The setting "TokenForge presets" has three choices:

  • Replace the theme presets (the starter value) shows only TokenForge's, under plain names such as primary, text-m and space-m.
  • Beside the theme presets shows the theme's and TokenForge's together. TokenForge's names start with tf-.
  • Off shows the theme's presets only.

With Replace, "Map the theme's old preset names to the nearest tokens" points the theme's old preset names at the nearest token, so existing posts and the theme's own styles keep their look. It adds CSS only and never changes your content. Where the theme uses one of TokenForge's names for another value (a white "base" in a theme, for example), the theme keeps the name and TokenForge's preset gets tf- in front.

TokenForge never changes the styles you saved in the Site Editor. A preset list you saved there still shows first in its picker. The Site Editor parts need a block theme. Presets, patterns and button styles work with any theme.

Editor interface

These switches change how the editor looks and opens for you. Nothing here reaches your pages.

  • Class field on top of the block sidebar: classes show as chips and TokenForge classes are suggested as you type. It edits the block's Additional CSS classes.
  • Compact, builder-style block settings: one setting per row with its name on the left, smaller fields and the Styles tab in the builder order.
  • Block settings on the left, List View on the right: swaps the two sidebars.
  • Drag the sidebars wider or narrower: a handle on the inner edge of each sidebar. You can use the arrow keys, and a double-click goes back to the normal width. Each browser keeps its own widths.
  • Default unit for sizes is the unit an empty size field starts with (rem by default; px keeps WordPress as it is). Values you already set keep their unit. Border width offers only px, %, em, rem, vw and vh, so another choice leaves it on px.
  • Open every settings panel, Styles tab first, List View open and Inserter as a list, one block per row.
  • Dark editor interface gives the editor header, sidebars and menus the dark look of the TokenForge window. Dark canvas shows the canvas in the site's dark scheme while you edit. It needs Dark mode on under Colors.

Canvas, content and window

  • Canvas: outline containers, and outline every grid and flex container. Only you see them.
  • TokenForge patterns adds five ready patterns to the inserter, under the category TokenForge: hero, cards, pricing, questions and answers (faq), and contact. They are built with TokenForge classes and never change existing content.
  • Button styles from your button families adds a style to the Button block for each family (the class is is-style-tf-primary and so on), under Styles in the block sidebar.
  • Hide blocks from the inserter takes block names separated by commas, such as core/verse, core/pullquote. Blocks already in your content keep showing and can still be edited.
  • TokenForge button in the editor header opens the dashboard as a window, for administrators.

Also in the block editor

  • Placeholder text recipes (?ipsum-short, ?ipsum, ?ipsum-long) expand in the canvas: type the name, then a space (it stays) or a semicolon.
  • Your self-hosted font families can be listed in the font picker (Typography > Self-hosted fonts).
  • The Light/Dark Toggle block adds a colour scheme switch.
  • Developers can add to the class field with tokenforge_editor_classes and load their own assets with tokenforge_block_editor_enqueue.

Forms, WooCommerce and other features

Forms

The Forms screen styles form fields everywhere and, in a builder that supports it, adds extras to the builder's own form element. No new elements are added, and the answers reach the email, webhook, saved submission and other actions as before. Each part has its own switch. The Builders section lists the builders that have the form tools.

  • Looks. Put .form--light or .form--dark on the form (or around it) and the whole form follows: field colours, spacing, labels, messages and the submit button in your button style. The classes form--columns, form--inline, form--compact and form--card are ready layouts. form--underline, form--rounded and form--soft are style presets.
  • Steps, conditions and calculations. Tick "New step starts here" on a field to split the form into steps, with Back, Next and a progress display. Next checks the fields of the step first. "Show only when" shows a field only for a certain answer. "More conditions" takes one line each, such as {Budget} > 1000, with all or any. A field can also be required only when another field has a given answer. Calculate ({Quantity} * {Price} + 25) makes a live result that is worked out again on the server. Hidden fields are not sent and never required.
  • Field types. A slider, star ratings, a range with two handles, input masks (# is a digit, @ a letter, * either) and a character counter.
  • Date rules. Earliest and latest day, weekdays that cannot be picked, and closed dates. They are checked again on the server.
  • Messages. Your own error message for each rule of a field.
  • Choices from your content. A select, radio or checkbox field can take its options from posts, terms or users.
  • Live values. {tf_form_value:Field} shows an answer anywhere on the page as the visitor types. {tf_form_count:form ID} and {tf_form_left:form ID} show how many times a form was sent and how many places are left.
  • Limits. Close a form after a number of sends or a date, allow only signed-in visitors, allow one send per user, and keep the send button disabled or hidden until your conditions hold. The limit counts sends, not people. For places that matter, also use the form's CAPTCHA or "Only signed-in visitors can send" with "Sends per user".
  • Actions. "Update meta" writes answers to the post or user meta you choose. "Add to cart" adds a product with a price worked out on the server from the calculated field.
  • Presets. Ready-made forms (contact, quote calculator, booking request, sign-up, profile edit, newsletter), single fields, and your own saved presets, which you can export and import between sites.

Form submissions adds to the builder's own submissions screen without changing its table: search, one entry laid out, read and unread marks with a count in the menu, statuses (new, done, spam), private notes, column choice, editing an entry, and export of ticked rows as CSV or JSON. Cells that start with =, +, - or @ get a leading quote in an export, so a spreadsheet does not run them. "Who can use these" sets the lowest role. Editing answers and deleting always need an administrator.

Delete old submissions automatically removes submissions older than a number of days, once a day. Nothing is deleted until you run a Dry run, look at what it would remove and confirm it. After you change the days, it waits for a new dry run. Each form can also have its own number of days in its Save submission settings.

WooCommerce

While WooCommerce is active, the WooCommerce screen styles your shop with your tokens: shop, product, cart, checkout and account pages, product cards and filters, header carts, and the Cart, Checkout, Mini-Cart and product blocks. Every part has its own switch: Shop pages, Buttons, Prices, Sale badge, Ratings, Notices, Fields, Product grid, Product filters and Blocks. Look and spacing and Tables, tabs & pagination hold shared styles.

  • Load shop page styles (Shop pages) is "Only where the shop appears (lighter pages)" or "On every page". Developers can decide per page with the tokenforge_woo_shop_styles filter. Header carts are styled everywhere either way.
  • Remove WooCommerce's own stylesheets stops WooCommerce loading its stylesheets. Some parts, such as the loading spinner and star icons, then need your own CSS. Win over element settings made in the builder makes the shop styles win over settings on single builder elements.
  • Product grid keeps the number of columns set in WooCommerce and uses the columns you set for the s and xs breakpoints on smaller screens. "Show products as cards" uses the Cards settings.
  • Blocks styles only colours and corners inside the WooCommerce blocks, so their layout stays as WooCommerce made it. With a block theme, "Block themes: prices, sale badges and ratings through global styles" lets those blocks take their look from global styles, so you can change them in the Site Editor.

Accessibility

  • Palette contrast. Checks text, links, focus rings and buttons against their backgrounds, in light and dark mode. The WCAG 2 ratio decides: at least 4.5:1 for text and links, and 3:1 for focus rings (level AA). The APCA value (Lc) is shown beside it for information only. Each failing pair has a "Use" button with the name of the nearest colour token that passes. Another colour lets you pick a token or any colour and see the ratio first. A fix changes only that pair's colour setting, never the token. Save keeps it and History can undo it.
  • Automatic accessibility attributes. Seven switches, all off. Each adds an attribute on the page only where it is missing: hide icons in links and buttons that have text, alt text from the media library on images with no alt, the menu name as the label of unlabelled menus, mark the menu link to the current page, announce links that open a new tab, and two guesses (the placeholder as the label of a field, and a label for a link with only an icon) that you should check. Anything you set yourself, even an empty alt="", is never changed, and nothing is saved in your pages. Put data-tf-a11y="off" on an element to leave it and everything inside it alone. This needs WordPress 6.2 or newer. Hiding icons and the icon-link guess need 6.5.
  • Focus gives a visible keyboard focus ring and a skip link styled as a button. Reduced motion respects the visitor's device setting. The External-link indicator adds a small glyph to links that open in a new tab, read to screen readers as a label. Canvas badges has two switches, "Heading levels" and "Focus order". They show a badge on every heading and number the links, buttons and fields in the order the Tab key visits them, in the builder canvas, for you only. Both are off on a new site.

Other components

  • Buttons. Any btn--* class makes a button. "Families (comma separated)" picks the colour families that get a class, with optional dark and light variants and outline variants.   • Design token files. See Import, export and reset.

AI agents

TokenForge's tools for AI agents are on by default (Options > AI agents). They are read only and are available to logged-in users who can edit content. An agent that builds your site through the WordPress MCP Adapter, or through the builder's own AI tools, sees four tools and is told to use TokenForge classes and variables instead of hard-coded CSS, and to name its own classes in BEM:

  • tokenforge-get-framework: the framework guide. The agent should call it first.
  • tokenforge-search: finds a class, variable, recipe or data attribute by words.
  • tokenforge-check-css: checks CSS (and optionally HTML) for hard-coded values and misspelt classes before saving.
  • tokenforge-get-recipe: returns the CSS of a recipe.

To connect an AI client (Claude, ChatGPT, Cursor and others):

  1. Install and activate the WordPress MCP Adapter plugin. In a builder with its own AI screen, that screen can install it for you and walk you through every step.
  2. Create an application password for your user: Users > Profile > Application Passwords.
  3. Add the site to your AI client as an MCP server that runs npx -y @automattic/mcp-wordpress-remote@latest, with three environment values: WP_API_URL (your site's /wp-json/mcp/mcp-adapter-default-server), WP_API_USERNAME (your user name) and WP_API_PASSWORD (the application password).
  4. Ask the agent to call tokenforge-get-framework first. The server instructions already tell it to.

Two switches under Options > AI agents turn the tools and the guidance off.

Import, export and reset

Everything is on Import, export & reset. Before every save, import, reset, restore and setup, TokenForge keeps a copy of your settings, so each of these can be undone under History.

Export and import

  • Download export file saves every TokenForge setting, token, colour family and font as one JSON file named after your site and the date. Keys that look like secrets (licence, token, password) added by an add-on are left out.
  • Choose export file loads a file made with Export. A list of the parts it holds appears: Tokens, Colour families, All settings, Module switches, Recipe settings and Fonts. Untick what you do not want, then press Import and confirm. The same parts on this site are replaced, and the rest stays as it is.

Design token files

  • Download token files gives two W3C design token files for Figma, Tokens Studio and Style Dictionary: tokenforge.tokens.json with every colour, size, font and shadow (light values), and tokenforge.dark.tokens.json with the colours that differ in dark mode. Fluid sizes go out as their desktop size, with the full range kept for the way back. A note says how many tokens were exported and which were left out, and why.
  • Choose tokens file (and Choose dark file (optional)) load files of up to 2 MB. You see what would change first: how many tokens are new, changed, unchanged or skipped, with each value. Press Apply to take the changes. Changed and new tokens are saved as your own tokens, after a history copy.

Reset to defaults

Choose what to reset: All settings (every switch and value), Tokens and colour families (the starter colours) and Font list (the files stay in uploads). Press Reset to defaults and confirm. It puts TokenForge back to how a new site starts, with the Effects module off. You can undo it under History. On any single field, the small reset button next to its name puts that one default back.

History

TokenForge keeps the last 20 copies. The table says when each was taken and what triggered it: before a save, an import, a reset, the setup wizard or a restore. What changed lists the differences between that copy and now. Restore puts a copy back after a confirmation. The restore takes a copy of the current state first, so it can be undone. Your pages are never touched.

Importing another framework's settings

The panel "Settings importer" brings over the variables and settings of another utility framework. It works even after that plugin was deactivated.

  1. Open Import, export & reset, then the panel Settings importer.
  2. Press the import button in that panel and confirm. The imported variables are merged into your tokens, and same-named tokens are overwritten. The imported settings replace the matching TokenForge settings: colours, scales, layout, typography, buttons, cards, icons, components, overlays, effects, builder options and fonts.
  3. Read the message that follows. It gives the number of variables and settings imported. "Last import" lists, for each part, what was mapped.
  4. Check Colors, Typography and Accessibility, then look at a few pages on the front end and in the builder.
  5. Move any custom CSS into your builder's own CSS box. Custom CSS is not imported.

When the other framework is a newer version, its site colour scheme ("light only", "dark only" and "light dark" become Light, Dark and Follow the visitor) and the card inner radius come across. Its "standard" card radius has no match in TokenForge and is named in the report. The import also brings over the default button effects, where the block editor class field sits, the floating dashboard button on the site's pages, and whether switched-off classes are hidden from the builder class list. If something is wrong, open History and restore the copy from before the import.

Options worth knowing

  • Inline the stylesheet (Performance) prints the CSS in the page, so there is no extra request, but the browser cannot cache it on its own. A new site starts with it on. Switch it off to link the stylesheet file instead.
  • Hot-reload CSS in open tabs after Save (Performance) updates other open tabs of your site without a reload.
  • Cascade layers put parts of the stylesheet in CSS layers, so your own CSS wins without extra specificity.
  • Dashboard look (the setting is called "Look") sets how the dashboard and the TokenForge window look: "Builder panels (default)", "Flat" or "Light". Save to apply it.

WP-CLI reference

All commands start with wp tokenforge. Import and restore take a history copy first, so they can be undone.

CommandWhat it does
wp tokenforge regenerateRebuilds the stylesheets.
wp tokenforge export > tokenforge-export.jsonPrints every setting, token, colour family and font as JSON. Redirect it to keep it in a file.
wp tokenforge import <file>Imports an export file (2 MB at most). --parts=tokens,palette picks parts from tokens, palette, settings, modules, recipes and fonts. --dry-run shows what would change and writes nothing.
wp tokenforge snapshotTakes a history copy now, unless nothing changed since the last one. --note=before-release adds a short label (letters, digits and dashes).
wp tokenforge historyLists the history copies, newest first. --format is table, json, csv, yaml or count.
wp tokenforge restore <id>Puts a history copy back. --yes skips the question.
wp tokenforge statusShows the version, the stylesheet files, the active builders and the number of history copies. Writes nothing. --format is table, json, csv or yaml.
wp tokenforge contrastChecks text contrast. It exits with code 1 when a pair fails, so it can stop a release. --all lists passing pairs too. --format is table, json, csv or yaml.

For developers

Put your code in a child theme's functions.php or in a mu-plugin, never in TokenForge's own files, so an update does not remove it.

Add SCSS from code

The filter tokenforge_global_scss receives an empty string and returns SCSS. TokenForge compiles it with its own mixins and functions and adds it last to the stylesheet. A compile error never breaks the site.

add_filter( 'tokenforge_global_scss', 'my_pricing_scss' );
function my_pricing_scss( $scss ) {
	return $scss . '.pricing { padding: var(--space-m); }';
}

PHP filters

  • tokenforge_global_scss: SCSS added last to the stylesheet (above).
  • tokenforge_recipes: add or change recipes.
  • tokenforge_editor_classes: the classes the block editor class field suggests.
  • tokenforge_woo_shop_styles: true or false, whether this page loads the shop styles. It gets true when the page shows shop content.
  • tokenforge_woo_global_styles: whether the WooCommerce price, sale badge and rating blocks take their look from global styles. The default is true with a block theme.
  • tokenforge_header_selectors: the CSS selectors used to find the header when its height is measured on the page.
  • tokenforge_css_dir: the folder the stylesheets are written to (an absolute path).
  • tokenforge_transfer_parts and tokenforge_transfer_export_data: add parts and data to an export.
  • tokenforge_starter_parts: add parts to Reset to defaults.

PHP actions

  • tokenforge_builder_enqueue: load an add-on's scripts and styles in the editor of every supported builder. It passes the builder: bricks, etch, oxygen, breakdance, elementor or divi. It fires for users who can edit posts, after TokenForge's own assets. Use wp_enqueue_script and wp_enqueue_style as usual. Where the builder's editor skips the WordPress queue, TokenForge prints them.
  • tokenforge_block_editor_enqueue: the same for the block editor. It passes the editor switches.
  • tokenforge_transfer_imported: runs after an import, with only the parts you selected.
  • tokenforge_starter_reset: runs after a reset.

Dashboard filters (JavaScript)

The dashboard runs these filters through wp.hooks in the browser: tokenforge.sections (add a section), tokenforge.nav (add a sidebar entry), tokenforge.icons (add an icon), tokenforge.render (draw a section that has its own render type), tokenforge.section_html (add a panel to a section), tokenforge.import_labels (name the parts an add-on adds to the import list) and tokenforge.reset_parts (add a part to the Reset to defaults list).

Frequently asked questions

Do I need a page builder?

No. The stylesheet loads on the front end and in the block editor on any WordPress site. The builder tools switch on only when a supported builder is active.

Will it slow my site down?

No CSS is built while a page loads: TokenForge writes one static stylesheet when you save. A new site prints it inline (Options > Performance, Inline the stylesheet). You can switch off any module you do not use at Home, and leave out the utility classes your site does not use. The shop styles are in a second file that loads only where the shop shows.

Can I add my own CSS?

Yes. Use the builder's own custom CSS box (or the CSS of the builder's theme style), or your theme's Additional CSS in the Customizer. Developers can add SCSS from code (see For developers).

What happens when I deactivate or delete TokenForge?

  • Deactivate: the stylesheet stops loading. Your settings stay.
  • Delete: its settings, its history copies, the generated stylesheets, the notes and statuses it kept for form submissions (the builder's own saved submissions stay) and the variables, colours and classes it added to the builder are removed. On a multisite network every site is cleaned. Font files you uploaded stay in uploads/tokenforge/fonts/, because other CSS may still use them.
  • Two builder settings are not put back. A theme style kept in step with TokenForge keeps its var(--...) values, which no longer work once the variables are gone, so set those fields again or pick another theme style. Builder settings the setup wizard changed stay as the wizard left them.

Does "Close after this many sends" stop one visitor from taking every place?

No. The limit counts sends, not people. One visitor or a script can send the form until it closes, and two sends at the same moment can both get the last place. For places that matter, such as event seats, also turn on the form's CAPTCHA or "Only signed-in visitors can send" with "Sends per user".

How do I load the shop styles on every page?

Set WooCommerce > Shop pages > Load shop page styles to On every page.

Can I translate TokenForge?

Yes. The dashboard and the builder settings use the tokenforge text domain, so translations from translate.wordpress.org load by themselves. This manual is in English only.

Troubleshooting

  • A change does not show on the site. Press Save: the stylesheet is built on save. Regenerate rebuilds it without other changes. Then clear any page cache or CDN cache your site uses.
  • A class does nothing. Check that its module is on at Home and its family is on under Options > Utility framework. A -at-{bp} class needs Breakpoint variants. If "Leave out unused utility classes" is on, press Scan now, or add the class to "Always keep these classes".
  • Effects do not play. The Effects module starts off on a new site: switch it on at Home. Visitors who ask for reduced motion see no movement, on purpose. In the builder, "Keep scroll & visible effects still in the builder canvas / block editor" holds them still while you edit.
  • The builder does not show TokenForge's variables or classes. Check the switches under Options > Builder sync, then reload the builder.
  • The block editor looks the same after a change. Reload the editor after you save the Block editor screen. The dark canvas needs Dark mode on under Colors.
  • A font upload gives WOFF, not WOFF2. Your server lacks the Brotli extension. WOFF works in every current browser.
  • Home warns about colour pairs. Open Accessibility > Palette contrast and use the suggested fix.
  • Something went wrong after a save, import or reset. Open Import, export & reset > History and restore the copy from before it.

Privacy and external services

Google Fonts

TokenForge contacts another server only when an administrator asks it to, and there is one such service: Google Fonts, when you press Download to this site (Typography > Self-hosted fonts). Your server asks fonts.googleapis.com for the family's CSS, then downloads the font files from fonts.gstatic.com, once. It sends the family name, the weights and styles you picked, and your server's IP address, like any web request. The files are stored in uploads/tokenforge/fonts/, so your visitors never contact Google. Google's terms are at developers.google.com/terms and its privacy policy at policies.google.com/privacy.

The accessibility checker (axe-core) is bundled with the plugin and runs only in the builder when an administrator presses Run check. Nothing else is contacted.

What TokenForge keeps about visitors

  • A form with a send limit keeps a count of its sends on your server.
  • A form limited per user keeps the time of each signed-in user's last send in their user data.
  • The Update meta action writes the answers you map to the post or user meta you choose. The Add to cart action puts the answers you allow on the cart item and the order.
  • Two things stay in the visitor's own browser (local storage): their light or dark choice when you show the switch, and, only for forms with "Remember answers on this device" on, what they typed until the form is sent. Passwords, files and hidden fields are never kept, and the saved answers are removed after a successful send.
  • Deleting TokenForge removes its send counts and the per-user send times.
